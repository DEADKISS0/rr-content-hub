# Flujo operativo de una pieza

## Principio

Una pieza nunca cambia de fase sin una acción explícita, un responsable y una confirmación visible. El historial conserva la decisión para que el contexto no vuelva a vivir en WhatsApp.

## Máquina de estados

1. **Borrador** — Owner/creativa completa título, objetivo, referencia y briefs iniciales.
2. **Idea por aprobar** — Cliente aprueba, pide ajustes o archiva.
3. **Idea aprobada** — Se desbloquea guion; aún no se programa rodaje.
4. **Guion en construcción** — Guionista adjunta enlace o archivo y define secuencia, diálogo, tomas y cierre.
5. **Guion por aprobar** — Cliente valida exactamente lo que se grabará.
6. **Guion aprobado** — Producción confirma sesión, responsable y locación.
7. **Rodaje** — Cámara y talento ejecutan el brief.
8. **Crudo cargado** — Cámara centraliza el material y releva a edición.
9. **Edición** — Editor añade V1/V2/final sin sobrescribir entregas anteriores.
10. **Revisión final** — Owner/cliente valida corte, copy y formato.
11. **Publicado** — Publisher registra plataforma, URL y fecha.
12. **Cerrado** — RR conserva aprendizaje, evidencia y trazabilidad.

## Reglas de seguridad funcional

- Solo el cliente aprueba una idea o un guion en la versión autenticada.
- El rodaje no inicia sin guion aprobado.
- Un archivo se clasifica como referencia, guion, crudo, edición V1/V2/final o evidencia de publicación.
- “Publicado” no equivale a “cerrado”: falta registrar resultado y aprendizaje.
- El actual workspace local sirve para validar UX; Supabase reemplazará su almacenamiento sin cambiar estas reglas.
